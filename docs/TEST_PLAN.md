# Selenium test plan

## Environment
Java 17+, Maven 3.9+, Chrome/Chromium installed; application available at http://localhost:8080. Selenium 4 Selenium Manager resolves the driver. Run application in one terminal with `mvn spring-boot:run`, then run tests in another with `mvn -Dheadless=true -DbaseUrl=http://localhost:8080 test`. Capture report at `target/surefire-reports/`.

## Test cases
| ID | Journey | Expected result |
|---|---|---|
| UI-01 | Open home | Complaint form and submit control visible |
| UI-02 | Submit valid complaint | Confirmation and CCP reference shown |
| UI-03 | Track new reference | SUBMITTED status shown |
| UI-04 | Reviewer approves pending complaint | Reviewer list reflects APPROVED |
| UI-05 | Track unknown reference | Not-found message shown |

Current automated class implements UI-01 through UI-04 and unknown-reference UI-05. Browser tests require the application to be running separately. To capture failure screenshots, wrap each test with a JUnit extension or catch test failures and save `((TakesScreenshot) driver).getScreenshotAs(OutputType.FILE)` into `target/screenshots`; screenshots are environment evidence and are not generated by CI configuration automatically.

## Failure policy
Any failed assertion or browser setup error fails Maven's test phase. Jenkinsfile runs tests before packaging/image creation, so test failures stop the pipeline before deployment/publish. Review `target/surefire-reports/*.xml`.
